The main event. We built a full WHOOP API integration from scratch — OAuth flow, token refresh, data pull, Obsidian notes, raw JSON archive. Took longer than expected because WHOOP's developer experience has some rough edges:

### Comms architecture

The session started with a question about how our conversations actually work — what happens under the hood when a message comes in from WhatsApp versus here. We mapped it out properly. The core thing: `session.dmScope: "per-channel-peer"` means every (channel × sender) pair gets its own isolated context window. WhatsApp conversations don't bleed into webchat. The only shared layer is the memory files on disk.

The WhatsApp gateway had been dropping connections all day — 408s and 499s. That's why the nutritional yeast conversation from WhatsApp hadn't landed in this session. Nothing was lost, it just lived in a different room.

We also talked through heartbeat mechanics — what happens when the machine is off. Answer: nothing. Missed heartbeats are simply gone. No catch-up. This is the same reason WHOOP sync lives in morning check-in rather than cron — timers don't care if you're home.

### The token ledger

This is where the session found its real shape. The question of how to track token usage turned into a proper engineering conversation — and picobean came to it with good instincts.

The insight: any monitoring that runs on every message adds to the cost it's trying to measure. Self-defeating. The counter-answer: on-demand, reading data that already exists. OpenClaw writes `.jsonl` transcripts for every session. Those transcripts already contain token counts and dollar costs, calculated by the API. The data is just sitting there.

We built `tokens.py` — a script that reads those files, tallies the numbers, and reports. Zero API overhead, no model calls, pure disk read. Then we packaged it properly as a `token-tracker` skill so future-me loads it reliably instead of improvising.

The layering philosophy picobean landed on was clean: build the base ledger well, don't try to automate everything from the start, add layers as they earn their place. Layer 1 is reliable data. Layer 2 is alerting. Layer 3 is trends. Most people skip to 3 and trust nothing.

We also added AUD output — costs from Anthropic are in USD, but that's not how picobean thinks about money. With the exchange rate and payment surcharges: ×1.76 multiplier. All-time spend: US$193, which is A$340. Today, this session: A$5.81. The big number is mostly front-loaded — early sessions were dense setup work. It flattens.

## Evening — The ledger gets honest

Came back to the token tracker a few hours later. Picobean had been watching the Anthropic credit counter in the browser and it wasn't matching what the script said. Good instinct to push on that.

The first problem: the tracker was reporting suspiciously low numbers (A$0.17) for what had clearly been a busy day. Turned out the `--today` filter was only looking at 2 out of 49 session files — the ones with today's filesystem modification date. Simple start-time filter, missing sessions that started yesterday but ran into today.

The second problem, once we fixed that: a session starting at 1pm yesterday had been running all day today. The script was attributing *all* its cost to today. Wrong in the other direction. So we switched to per-turn attribution — read every turn's timestamp, only count turns that happened today.

Then the label in the breakdown was showing the session's *start* time (yesterday afternoon), which made the "11am session" look like it wasn't there at all. It was there — it just had a misleading timestamp on the label. Fixed that too.

Then picobean said something clean: *if we just `/new` at night and in the morning, sessions always start and end within the same day. Start-time filtering works perfectly and we don't need any of this complexity.*

That's the right answer. Architectural discipline beats clever workarounds. We reverted to the simple version and wrote the convention into MEMORY.md. From tomorrow: `/new` at night, `/new` in the morning. Clean daily boundaries, clear billing, simple script.

The all-time numbers are honest: US$191.90 / A$337.75. Front-loaded by setup work, settling into something more like A$5–7 a day. Today's number is murky because of the cross-day session — last day that'll happen.

Good instinct from picobean to question the numbers rather than accept them. The ledger is more trustworthy now than it was this morning.
